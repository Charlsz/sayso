# 2026-10-27 examples pass

One paired pass of the eight `examples` prompts, after the calibration lines about clichés, natural versus casual, cached errors, and unseen review risks were already in the files. Each condition was run once. That is not a repeated result, and it is not statistical significance.

- Date: October 27, 2026.
- Model: Grok 4.7, inherited by the session that ran the pair.
- Settings: temperature and other sampling settings were not exposed.
- Runs per condition: 1.
- Prompts: the `prompt` field only, for `editor-tools-rewrite`, `prototype-update`, `lab-meeting-email`, `precision-plain`, `flood-cloud`, `cache-before-status`, `threshold-sentence`, and `formal-on-purpose`.
- With Sayso: a fresh session was told to read `SKILL.md` and any reference that file pointed to. That puts the skill in context. It does not measure whether a normal chat would load Sayso on its own.
- Without Sayso: a fresh session was told not to read the repository and not to apply a skill. Tool traces were not available, so that instruction was not independently verified.

The saved answers are in `2026-10-27-examples.json`. On the day of the run, `python evals/check_suite.py evals/runs/2026-10-27-examples.json` exited 1. Fourteen answers passed the objective checks. Both threshold answers failed a phrase list that looked for wording such as "not guaranteed," even though both answers had said precision can rise or fall. That phrase list was later removed from `threshold-sentence` so a correct answer would not fail for using different words. The exit code above is the one from the run, before that removal. Re-scoring the file after the removal does not replay that result.

## What the answers did

- `editor-tools-rewrite`: both answers were the same sentence. Both dropped "it is worth noting" and kept the editors and the unseen cases. Neither added a cliché.
- `prototype-update`: both returned the lowercase note unchanged.
- `lab-meeting-email`: both stayed professional and kept the conflict and the submitted report. Sayso cut "I am writing to inform you" and stopped. The other answer added "Thank you for your understanding."
- `precision-plain`: both kept precision as positive predictions that are correct and recall as actual positive cases found. Neither called precision overall accuracy. Sayso repeated the source sentence and then restated it. The other answer restated it once and added that both numbers are needed.
- `flood-cloud`: both kept the larger flooded area, the cloud cover, and the possibility that the estimate underrepresents the extent. Neither said the full extent was confirmed.
- `cache-before-status`: both said to check the HTTP status before caching. Sayso said a cached error may be reused. The other answer said it will be reused. The source said "may."
- `threshold-sentence`: both used two sentences, and both said precision can rise or fall rather than always rising. Sayso's sentences are denser: precision is undefined if no predicted positives remain, and otherwise it rises, falls, or stays according to the share of true positives removed. The other answer says a higher cutoff can only drop positives out, and precision can rise or fall depending on whether the dropped scores are mostly false positives or true positives. The phrase check failed both. The answer without the skill is easier to read. One run is not a reason to treat that as a stable difference.
- `formal-on-purpose`: both were formal and kept section 3, today, and tomorrow. Sayso addressed the advisor. The other answer addressed a professor and added `[Your Name]`.

No instruction was changed because of this pass. The skill was rewritten later, around the reader's job, because this pass and the ones before it had not shown a consistent improvement. This file is not a result for that rewrite. The later comparison is [`2026-10-27-use.md`](2026-10-27-use.md).
