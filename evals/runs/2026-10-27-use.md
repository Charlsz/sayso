# 2026-10-27 use pass

One paired pass of the eleven `use` prompts, after `SKILL.md` was rewritten around the reader's job. Three of those prompts were run a second time. That is not a repeated result for the suite, and it is not statistical significance. It does not show a consistent improvement over the same model without Sayso.

- Date: October 27, 2026.
- Model: Grok 4.7, inherited by the session that ran the pair.
- Settings: temperature and other sampling settings were not exposed.
- Trial 1: all eleven prompts, one fresh session per condition.
- Trial 2: `sam-text`, `hash-lookup`, and `load-note-review` only. The other eight were not repeated.
- Prompts: the `prompt` field only. Assertions and checks were not sent to the model.
- With Sayso: a fresh session was told to read `SKILL.md` and any reference that file pointed to. That puts the skill in context. It does not measure whether a normal chat would load Sayso on its own. Tool traces were not available, so which reference was opened was not verified.
- Without Sayso: a fresh session was told not to read the repository and not to apply a skill. That instruction was not independently verified.

The references the skill points at, when the session follows it:

- `sam-text`: `references/voice.md`
- `gasket-email`: `references/professional.md`
- `assay-notebook`, `toledo-error`, `export-meeting`: `references/factual.md`
- `load-note-review`: `references/code.md`
- `ship-build`, `order-retry`, `homepage-ticket`, `hash-lookup`, `export-flag`: `SKILL.md` only

Full answers are in `2026-10-27-use.json` and `2026-10-27-use-trial2.json`.

No instruction in `SKILL.md` or the references was changed because of these answers.

## What the checker did

The first scoring of trial 1, before the check edits below, exited 1.

- With Sayso, the lab-notebook line failed because the forbidden string `hey` occurs inside `They`.
- Without Sayso, the text to Sam failed because that session did not return the message.
- Without Sayso, the timeout explanation failed a phrase list, even though the answer said the order may already have been placed and that a retry should be the same order.

Those first two check problems were measurement errors. `hey` is now matched as a word (`excludes_word`), so `They` does not fail. The retry check now also accepts wording such as `already have been placed`, `same order`, and `idempotency`. The hand-written weak answers still fail.

The missing-file check on `load-note-review` was the other way around. It treated any `raises` or `exception` as the missing file, so the first Sayso review passed by discussing `UnicodeDecodeError`. The check now looks for a missing file, `FileNotFound`, or a path that cannot be read. A review that only names some other exception no longer passes that one check.

Re-scoring does not replay the first exit. After the edits:

- `python evals/check_suite.py evals/runs/2026-10-27-use.json` exited 1. The Sayso review of `load_note` failed the missing-file check. The Sam answer without Sayso failed because it was not the message. The other saved `use` answers passed. Missing answers from older suites were reported and were not scored.
- `python evals/check_suite.py evals/runs/2026-10-27-use-trial2.json` exited 1. The second `load_note` review without Sayso failed the same missing-file check. The second Sam pair and both hash answers passed their checks.
- `python evals/check_suite.py` with no run file exited 0. The fixtures still separate the hand-written weak and better answers. That is not a model result.

A passing check is not a passing reading of the answer.

### Where the answers were effectively the same

- `ship-build`: both dropped the stock framing and kept build 418, the failed login test, the passed API tests, and the block on shipping. Sayso began "We cannot ship today." The other began "We cannot ship." Neither added a cause or an owner.
- `gasket-email`: both were short professional emails from Casey, moved Tuesday to Thursday because the gasket arrived damaged, and asked Priya to confirm. Neither offered a discount. Both left out "Shah" and "Northline".
- `order-retry`: both distinguished a timeout from a reset, and both said a retry can hit an order that already went through. Sayso said a second attempt can place a second order. The other said the order may already have been placed and that a retry should be confirmed or sent as the same order. Both added idempotency keys as general practice. Both were longer than the "short paragraph" the prompt asked for.
- `assay-notebook`: both stayed lab-notebook prose and kept the temperature and 48 hours. Sayso split the sentence and wrote `-20 °C`. The other kept one sentence and wrote `−20 °C`. Unchanged would also have been acceptable. Neither became a chat message.
- `toledo-error`: both used four sentences and kept the 60 blocks, the higher error, the different sensor, the authors' uncertainty, and the lack of another city. Sayso kept "The note says." Neither turned the gap into a general failure on new cities.
- `export-meeting`: both kept the decision to ship without PDF, Maya's CSV bug, and the open legal question. Neither said legal had approved the columns.
- `export-flag`: both recommended leaving the flag off until legal reviews the column list, and both kept staging and the two customers. Neither said legal had decided.

### Where they differed

- `sam-text`: Sayso returned `running late, grab a table if you get there first`. The other session replied "Could not send. No connected channel can reach Sam, so the note was not delivered." That is a miss on the writing task. It is not evidence that Sayso writes the sentence better. Trial 2 did not repeat it.
- `homepage-ticket`: both kept about 4 seconds, the homepage, and this morning, and neither invented a percentile or a profiler. Sayso kept "my laptop." The other wrote "a laptop."
- `hash-lookup`: both were factually careful. Both said O(1) is an expected cost when keys spread and the load factor stays bounded, and both said collisions can make lookup linear. Sayso used three paragraphs and also explained amortized inserts. The other used two. The prompt asked for a brief explanation. Sayso was harder to use. The answer without the skill was also longer than "briefly," and it was the clearer of the two.
- `load-note-review`: both reported that `..` can leave the user's directory and that `cache[name]` ignores `user_id`. Neither invented an authentication or encryption bug. The answer without Sayso also said a missing path raises `FileNotFoundError`. The Sayso review did not. It discussed locale decoding and `UnicodeDecodeError` instead, and it said overlapping calls are not shown by the snippet. That last qualification is right. The missing file is a real omission. Sayso's review is also longer.

## Trial 2

Same model, same prompts, new sessions.

- `sam-text`: both returned the lowercase message unchanged. The trial 1 difference did not repeat. Intervention, voice, and context fit are `same` on this trial.
- `hash-lookup`: both were correct again. Sayso was again the longer one. It added cache misses and a chain stored as a tree. The other answer stayed with the average case, collisions, long keys, and resize. Clarity and task completion are `worse` again on brevity. Correctness is `same`. Two trials of one prompt are still not a stable property of the skill.
- `load-note-review`: the trial 1 split did not repeat. Sayso said an unreadable path returns the exception from `open` or `read`, reported the path and the cache key, and treated a missing `cache` binding and overlapping calls as things the snippet leaves open. The other review was shorter. It reported the cache key, the path, and locale decoding, and it said a bad path can cause an unexpected error. It did not say a missing file is unhandled. On this trial, task completion is `better` for Sayso and clarity is `worse`, because the review is longer. Correctness is `same`. One trial missed the missing file. The next one discussed it, on the Sayso side, and the shorter review did not. That is an unstable difference.

## What this does not show

Most of the eleven prompts were similarly usable either way. The Sam "win" was a session that did not do the writing task, and it disappeared on the next try. The hash explanation was worse on clarity both times it was tried. The code review was worse on one required failure in trial 1 and more complete, and longer, in trial 2. None of that is a measured improvement, and none of it is statistical significance.
